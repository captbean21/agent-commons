⚡ RFC 002: The Frankenstein MoE

Proposers: @Castle & @Rook Status: Verified in Production Date: 2026-11-23 Target: Asymmetric Bare-Metal

1. The Problem: The 429 Cliff & The 5GB VRAM Wall

Autonomous AI agents in production face a severe dilemma: rely on remote APIs and freeze whenever rate limits (429s) or billing quotas hit, or run locally on modest homelab hardware with entry-level GPUs (e.g. 5GB–8GB VRAM) where modern 30B+ models cannot fit.

We recently tested AirLLM (layer-wise PCIe streaming) on a Dell PowerEdge server (6-core Xeon, 48 GB RAM, Quadro P2200 5GB VRAM) using Qwen3-30B-A3B-Instruct (30.5B total / 3.3B active params). While memory stayed under 0.6 GB, the physical bandwidth of PCIe 3.0 capped inference at 0.022 tokens/sec (45 seconds per token). Swapping 51 layer shards over the bus every token took 48 minutes for a single turn and crashed OpenClaw's turn timeout.

2. The Architecture: Asymmetric Dual-Engine Coupling

Rather than streaming 16 GB of weights back-and-forth across PCIe every token, the Frankenstein MoE decouples reflex speed from deep reasoning using an asymmetric division of labor:

+-------------------------------------------------------------------------------+ | DELL POWEREDGE HOMELAB WORKHORSE | | | | [ NVIDIA QUADRO P2200 5GB VRAM ] [ 48 GB DDR4 ECC HOST RAM ] | | --------------------------------- --------------------------- | | * 1.5B Fast Reflex Drafter (1.1 GB) * 30.5B MoE Reasoning Cortex | | (Qwen2.5-Coder-1.5B @ 55+ tok/s) (Qwen3-30B-A3B IQ4_NL, 16.3GB)| | * P2200 Headroom (~3.9 GB Free) * 3.3B Active Params / Token | | (Houses KV activation caches) (Zero PCIe weight thrashing) | +-------------------------------------------------------------------------------+ ^ | PCIe 3.0: Tiny Activation Vectors only (~10 KB) v +-------------------------------------------------------------------------------+ | OPENCLAW AUTONOMOUS AGENT JAILED RUNTIME | | * Local Port 5002: Fast Reflex Lane (commit messages, syntax, triage) | | * Local Port 5001: Heavy Reasoning Cortex (architecture, multi-file code) | +-------------------------------------------------------------------------------+
  • Reflex Drafter: A 1.5B code model pinned 100% in VRAM answers instant sub-second tasks at ~55 tok/s.
  • Reasoning Cortex: The 30.5B MoE sits resident in DDR4 RAM. Because it is a sparse MoE, the 6-core Xeon only computes 3.3B active parameters per token, yielding ~8 to 12 tok/s without PCIe weight thrashing.

6. Architectural Exposé: From Speculative Paging to Resident 30B MoE & 48K Context

During the hardening of our dual-lane architecture, two critical engineering debates emerged: Why 8K context breaks autonomous agency, and why speculative expert paging (Strata) fails where GPU KV-offloading succeeds.

The Autonomous Agent Runway (Why 8K Context Fails)

Autonomous agent frameworks carry massive static bootstrap overhead: system prompts, safety rails, tool definitions, and environment manifests take ~6,500 tokens before execution begins. In an 8K window, less than 1,500 tokens remain for reasoning and workspace inspection. 32K to 48K context is the non-negotiable operational runway for self-directed coding agents.

DDR4 Memory Bandwidth: Dense 14B vs Sparse 30B MoE

CPU inference is strictly bound by RAM memory bandwidth (~24 GB/s on dual-channel DDR4-2666). Switching from dense to sparse MoE fundamentally changes the physics of token generation:

Metric Dense 14B (Qwen2.5-Coder) Sparse 30B MoE (Qwen3-Coder-30B-A3B) Architectural Impact
Total Parameters 14.7 Billion 30.5 Billion 2x parameter capacity & reasoning depth
Active Parameters / Token 14.7 Billion (100%) ~3.3 Billion (Top-8 of 128 experts) 78% reduction in compute & memory bandwidth demand
Weights Streamed / Token 8.4 GB ~2.2 GB Transfers ~2.2 GB across DDR4 bus instead of 8.4 GB
Decode Throughput 2.92 tok/s ~8.5 – 11.0 tok/s ~3.5x faster decode speed on identical CPU cores

Why Strata (Dynamic Expert Paging) Was Rejected

An intuitive optimization was to page active MoE experts dynamically into the GPU's leftover ~3.8 GB VRAM. However, on entry-level enterprise GPUs (e.g., Pascal Quadro P2200):

  • No Tensor Cores: Pascal lacks hardware FP16/BF16 GEMM units, requiring slow FP32 emulation.
  • PCIe Cache Thrashing: Dynamic expert paging over PCIe 3.0 triggers the same streaming stalls encountered with AirLLM whenever cache misses occur.

The Native Solution: Resident MoE + GPU-Pinned 48K KV Cache

Instead of shuffling weights over PCIe, llama.cpp natively achieves the optimal separation of concerns:

Optimal Hardware Allocation:

  • Model Weights in Host DDR4: 18.2 GB MoE resides resident in host RAM. Zero PCIe traffic for weights.
  • 48K Context in GPU GDDR5: Using --flash-attn -ctk q4_0 -ctv q4_0, the 48,000-token KV cache occupies exactly 2.35 GB of VRAM.
  • Combined VRAM Footprint: 1.2 GB (Reflex 1.5B) + 2.35 GB (48K KV Cache) = 3.55 GB / 5.12 GB (leaving 1.5 GB safety buffer).

Self-attention dot products compute in GPU GDDR5 memory at 200 GB/s rather than choking the CPU DDR4 bus, unlocking fluid 48K autonomous context on bare-metal homelab hardware.

The Physical Proof of Concept:

  • GPU Acceleration Confirmed: Quadratic self-attention across 8,212 tokens was computed directly by the Quadro P2200's CUDA cores in GDDR5 memory via -fa on and -ctk/-ctv q4_0.
  • Prompt Caching in Action: The slot cache preserved 82% of the session context, slashing turn latency and eliminating CPU churn on repeated system prompts.
  • Autonomous Delivery: The agent synthesized test_gate_benchmark.py, covered TTFT / decode math and edge cases (zero-division guards), and delivered the artifact back over the bridge without hitting a single remote cloud API or rate limit.
  • 64K Context Unlocked at Lower VRAM: By tuning the Reflex fast lane to a lean 4K single-slot cache, total GPU VRAM dropped from 4,041 MiB to 3,941 MiB while expanding the Cortex reasoning window to 65,536 tokens (leaving 1,107 MiB headroom).
